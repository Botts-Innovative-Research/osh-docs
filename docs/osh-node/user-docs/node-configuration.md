# General Configuration

While you will be mainly configuring **OpenSensorHub** nodes via the Admin UI,
there are some important things to know about the node configuration,
as well as configuration for important **OpenSensorHub** modules.

This page goes over the *Config file*, *Network Settings*, and *Security Settings*.

## Config File
OpenSensorHub's configuration is centralized in a single file. It is in JSON format, so it can be easily viewed or modified in any text editor.

This file will be found at `/osh-node-*.*.*/config/config.json`.

### Config Saving

When the admin UI is opened the configuration file's modules are created into the admin UI automatically starting at the top of the config file and going down.

The easiest way to update the config file is to press the **Save** button.
This creates a `config.json` file that has all the modules and settings in admin UI.
The prevous config is kept as a backup

A *backup* would be named: `config.json.bak...`

To go back to a previous backup delete the current config and remove the `.bak` and the numbers after from the name of the *backup*.

### Common Config File Parameters
If you were to open the config file you would see these common parameters for each module:

- **objClass**: The class of the configuration object itself (needed for deserialization)
- **id**: Local ID of the module instance (uses hexacode)
- **description**: Description of the module instance (not always present)
- **autoStart**: Boolean flag indicating if the module should be automatically started when the hub starts
- **moduleClass**: The class of the module to instantiate
- **name**: Name of the module instance

:::info
deserialization - turning the raw data into a readable form\
hexacode - base-16 numbering system which uses sixteen symbols 0-9 and a-f\
instantiate - being used as a blueprint to create a class (or a module in this case)
:::

A module in `config.json` might look like:

```
[
  {
    "objClass": "org.sensorhub.impl.exampleConfig",
    ...
    "id": "01234567-89ab-cdef-0123-456789abcdef",
    "description": "this example is not a real module",
    "autoStart": true
    "moduleClass": "org.sensorhub.impl.example",
    "name": "Example Module"
   },
  ...
```

Any other parameter is specific to the module and should be described in the module documentation.

### Sensor Driver Configuration
System drivers share some common configuration properties inherited from the `SensorConfig` class:
- **serialNumber**: Unique identifier also found in processes
- **location**: Sensor location: latitude, longitude, and altitude
- **sensorML**: URL to a SensorML description (which will be merged with information generated automatically by the framework, see below)
- **lastUpdated**: Date when the SensorML description generated by the driver became valid.

:::note
Everytime lastUpdated is changed (or the validTime in the SensorML document is manually updated), the procedure description is versioned in OSH data stores.
:::

### SensorML

If a driver uses an external SensorML file, OSH combines it with information generated by the driver.

The driver-generated input, output, and taskable parameters take priority over the external SensorML.

If validTime, process name, or process description are missing from the SensorML file OSH generates it using the module's configuration
(lastUpdated, module name, and module description respectively)

### Datastore Identifiers

All storage modules will have **databaseNum**.
This is used by the *federated database* and must be a positive number and unique for that node.

## Network Config
In the *Network* tab, you can see the **OpenSensorHub** node's HTTP server configuration.
![networkconfig.png](..%2F..%2Fassets%2Fosh%2Fadminui%2Fnetwork%2Fnetworkconfig.png)
You can configure:
- Authentication
- CORS
- HTTPS/SSL
- Static content directory/URL.

### Static Content

The default static content directory in an **OpenSensorHub** node will be at: `/osh-node-*.*.*/web`. 

Any static web files that are placed here are available at the root URL.

The directory and URL can be configured in the node's HTTP server configuration.

## Security Config
Under the *Security* tab, you can manage access to the node using Users, Roles, Permissions

### General
This is information about the security module itself like name and ID

### Users
Each User have:
- User ID - different for each user also used for logging in
- Name - not required
- Password - used for logging in
- Role - which a user can have multiple of
- Permissions - allows access to things specific to that user

### Roles
Best for when there are many users that will share the Permissions

Each role have:
- Role ID - different for each role and how they are assigned to users
- Name and Description - not required
- Permissions - allows access to things for all users with the role

The standard permissions are the *Connected Systems API Service Module*, the *SOS Service Module*, and the *AdminUI Module*, which enables access-control of the Admin web interface.
